## Phase 5: Tool Integration and Testing

### Overview

Connect all 5 HR tools (Leave Balance, Benefits Info, HR Case, Team Availability, People Search) to the database by replacing hardcoded mock data with database queries. Remove RBAC checks since admin users have full access to all tools. Verify end-to-end functionality: admin edits data in admin panel → agent retrieves updated data through tool calls. This completes the bidirectional data flow and fulfills the core promise of the feature.

**Key Deliverables:**
- All 5 tools query database instead of mock data
- RBAC restrictions removed (admin users have full access)
- Artificial delays removed
- Tool return structures preserved for UI compatibility
- End-to-end integration tested and verified

## Notes for Implementation

### Database Query Handling
- All database imports should be dynamic to avoid circular dependencies
- Use proper error handling for all database calls
- Log database errors for debugging but return user-friendly error messages

### Session Context Approach
- For tools that need employee/manager context (Leave Balance, Benefits Info, Team Availability), document whether to:
  - Derive from authenticated session/Clerk user
  - Require as input parameter
  - Use admin access level to allow querying any employee

### Testing Strategy
- Each task should be tested individually as it's completed
- Integration tests should verify admin change → agent retrieval flow
- Performance tests should measure actual query times, not just UI feedback time

### Deployment Considerations
- Ensure database is migrated before deploying Phase 5 code
- Verify all query functions from Phase 2 are available in lib/db/queries
- Test with fresh seeded data to simulate demo scenario
- Have rollback plan if issues discovered post-deployment
