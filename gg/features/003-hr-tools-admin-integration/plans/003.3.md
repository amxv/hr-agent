# HR Tools Admin Integration - Phase 3: Admin UI - Employee Management & Leave Balances

## Phase Overview

Build the first half of the admin interface covering the HR data dashboard, employee directory, and leave balances management. This establishes the UI patterns that will be extended in Phase 4 for benefits, cases, and availability.

**Dependencies**: This phase depends on Phase 2 being complete (all tRPC procedures and queries implemented).

**References**:
- See `gg/features/003-hr-tools-admin-integration/summary.md` for the complete feature overview and implementation approach.
- See Phase 1 plan for Database Schema and Shared Type Definitions.

#### Patterns, Conventions, and Design Decisions to Reuse
- **Page Structure** - Server component pages that render client components
- **Dialog-Based CRUD** - All create/edit operations in dialogs, not separate pages
- **Form Pattern** - React Hook Form + Zod + shadcn/ui components
- **tRPC Integration** - Use `trpc.admin.procedureName.useQuery()` and `useMutation()`
- **Loading States** - Skeleton components during data fetching
- **Search Pattern** - Debounced search input with searchField dropdown
- **Pagination** - Load more or limit/offset pagination
- **Toast Notifications** - Success/error toasts using shadcn/ui toast
- **Styling** - Tailwind CSS with cn() utility for conditional classes

#### Key Constraints to work within
- All pages under `/app/admin/hr-data/` protected by admin middleware
- Use shadcn/ui components exclusively (Button, Dialog, Input, Select, Card, Table, etc.)
- Follow accessibility rules from CLAUDE.md (proper ARIA, keyboard navigation, etc.)
- No emojis unless user explicitly requests
- Mobile-responsive layouts
- Clear validation error messages
