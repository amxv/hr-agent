# HR Tools Admin Integration - Phase 5: Tool Integration and Testing

## Phase Overview

Connect all 5 HR tools to the database by replacing mock data with database queries. Verify end-to-end functionality: admin edits data in admin panel → agent retrieves updated data through tool calls. This completes the bidirectional data flow.

**Dependencies**: This phase depends on Phases 1-4 being complete (database, backend API, and admin UI all implemented).

**References**:
- See `gg/features/003-hr-tools-admin-integration/summary.md` for the complete feature overview and implementation approach.
- See Phase 1 plan for Database Schema and Shared Type Definitions.
- See Phase 2 plan for all available database query functions.

---

#### Files that won't be modified but are important to understand
- `lib/ai/tools/tools.ts:25-108` - Tool registry where all tools are registered
- `lib/ai/tools/tools-definitions.ts:74-98` - Tool metadata (names, descriptions, costs)
- `app/(chat)/api/chat/route.ts:549-564` - streamText invocation that uses tools
- `lib/db/queries.ts` - All HR query functions created in Phase 2

#### Files that need to be modified or extended
- `lib/ai/tools/leave-balance.ts` - Replace mock data with database queries
- `lib/ai/tools/benefits-info.ts` - Replace mock data with database queries
- `lib/ai/tools/hr-case.ts` - Replace mock data with database queries
- `lib/ai/tools/team-availability.ts` - Replace mock data with database queries
- `lib/ai/tools/people-search.ts` - Replace mock data with database queries

#### Patterns, Conventions, and Design Decisions to Reuse
- **Tool Structure**: Keep existing tool structure (description, inputSchema, execute function)
- **Streaming Updates**: Maintain dataStream.write() calls for UI feedback
- **Error Handling**: Use try/catch with detailed error messages
- **Logging**: Keep log.info and log.error calls for debugging
- **Return Structure**: Maintain exact same return structure for UI compatibility
- **Dynamic Imports**: Import query functions dynamically to avoid circular dependencies

#### Key Constraints to work within
- Tool return structures MUST match current mock data structure exactly
- UI components expect specific data shapes - do not break them
- Remove artificial delays (no more setTimeout)
- Remove RBAC checks (isManager, isHR) - admin users have full access
- Keep tool descriptions and input schemas unchanged (or improve clarity)
- Maintain backward compatibility with existing chat UI
