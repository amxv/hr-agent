## Phase 3: Admin UI - Employee Management & Leave Balances

### Overview

Build the first half of the admin interface covering the HR data dashboard, employee directory, and leave balances management. This phase establishes the UI patterns that will be extended in Phase 4 for benefits, cases, and availability. All components follow existing admin panel patterns (dialog-based CRUD, React Hook Form + Zod, tRPC integration, shadcn/ui styling).

**Phase Dependencies:** Phase 1 (Database Schema) and Phase 2 (Backend API and tRPC procedures) must be complete before starting Phase 3.

## Implementation Notes

### Component Organization
- All client components should use "use client" directive at the top
- All server components should be async functions
- Reuse existing shadcn/ui components (Card, Button, Dialog, Input, Select, Table, etc.)
- Follow the cn() utility pattern from `src/lib/utils.ts` for className composition

### Form Patterns
- Use React Hook Form + Zod for validation
- Extract form schemas to separate files (e.g., `src/lib/schemas/employee.schema.ts`)
- Reuse validation rules between create and edit dialogs
- Show loading states on form submission
- Use toast notifications for feedback (success/error)

### tRPC Integration
- All data fetching must use tRPC procedures (no direct API calls)
- Queries: Use `.useQuery()` hook for reading data
- Mutations: Use `.useMutation()` hook for create/update/delete
- Handle loading, error, and success states appropriately
- Use callbacks to refresh data after mutations

### UI/UX Patterns
- Dialog-based CRUD (no separate pages for create/edit)
- Confirmation dialogs before destructive actions
- Loading skeletons during data fetch
- Empty states with helpful messages
- Error messages that explain what went wrong
- Status badges for enum fields (color-coded)
- Icons for visual hierarchy (lucide-react)
- Hover effects and tooltips for complex fields

### Performance Considerations
- Implement pagination to avoid loading too many records at once
- Use debounced search to reduce query frequency
- Memoize expensive calculations (e.g., years of service)
- Lazy load heavy components if needed

### Data Validation
- Client-side validation with React Hook Form + Zod
- Server-side validation in tRPC procedures (uniqueness checks)
- Display validation errors below fields
- Clear, user-friendly error messages
