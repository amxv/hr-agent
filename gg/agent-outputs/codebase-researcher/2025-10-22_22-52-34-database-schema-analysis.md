#### Complex Delete: `deleteMessagesByChatIdAfterMessageId()` (lines 500-556)
```typescript
export async function deleteMessagesByChatIdAfterMessageId({
  chatId,
  messageId,
}: {
  chatId: string;
  messageId: string;
}) {
  try {
    // First, get the target message to find its position
    const [targetMessage] = await db
      .select()
      .from(message)
      .where(and(eq(message.id, messageId), eq(message.chatId, chatId)));

    if (!targetMessage) {
      throw new Error("Target message not found");
    }

    // Get all messages in the chat ordered by creation time
    const allMessages = await db
      .select()
      .from(message)
      .where(eq(message.chatId, chatId))
      .orderBy(asc(message.createdAt));

    // Find the index of the target message
    const targetIndex = allMessages.findIndex((msg) => msg.id === messageId);

    if (targetIndex === -1) {
      throw new Error("Target message not found in chat");
    }

    // Delete all messages after the target message (including the target itself)
    const messagesToDelete = allMessages.slice(targetIndex);
    const messageIdsToDelete = messagesToDelete.map((msg) => msg.id);

    if (messageIdsToDelete.length > 0) {
      await deleteAttachmentsFromMessages(messagesToDelete);

      return await db
        .delete(message)
        .where(
          and(
            eq(message.chatId, chatId),
            inArray(message.id, messageIdsToDelete)
          )
        );
    }
  } catch (error) {
    console.error(
      "Failed to delete messages by chat id after message id from database"
    );
    throw error;
  }
}
```

**Pattern**:
- Application-level transaction logic (not SQL transaction)
- Multiple queries for state validation
- Array manipulation (findIndex, slice)
- `inArray()` operator for IN clause
- Multiple condition AND with `and()`
- Attachment cleanup before deletion

### 5.6 File/Attachment Operations (Vercel Blob Integration)

#### Cleanup Function: `deleteAttachmentsFromMessages()` (lines 676-699)
```typescript
async function deleteAttachmentsFromMessages(messages: DBMessage[]) {
  try {
    const attachmentUrls: string[] = [];

    for (const msg of messages) {
      if (msg.attachments && Array.isArray(msg.attachments)) {
        const attachments = msg.attachments as Attachment[];
        for (const attachment of attachments) {
          if (attachment.url) {
            attachmentUrls.push(attachment.url);
          }
        }
      }
    }

    if (attachmentUrls.length > 0) {
      await del(attachmentUrls);
    }
  } catch (error) {
    console.error("Failed to delete attachments from Vercel Blob:", error);
    // Don't throw here - we still want to proceed with message deletion
    // even if blob cleanup fails
  }
}
```

**Pattern**:
- External resource cleanup (Vercel Blob storage)
- Error is not re-thrown (fail-safe for data deletion)
- Extracts URLs from JSON attachments field
- Called before message deletion to ensure cleanup

### Migration Execution: `lib/db/migrate.ts`
```typescript
import { config } from "dotenv";
import { drizzle } from "drizzle-orm/postgres-js";
import { migrate } from "drizzle-orm/postgres-js/migrator";
import postgres from "postgres";

config({
  path: ".env.local",
});

const runMigrate = async () => {
  if (!process.env.POSTGRES_URL) {
    throw new Error("POSTGRES_URL is not defined");
  }

  const connection = postgres(process.env.POSTGRES_URL, { max: 1 });
  const db = drizzle(connection);

  console.log("⏳ Running migrations...");

  const start = Date.now();
  await migrate(db, { migrationsFolder: "./lib/db/migrations" });
  const end = Date.now();

  console.log("✅ Migrations completed in", end - start, "ms");
  process.exit(0);
};

runMigrate().catch((err) => {
  console.error("❌ Migration failed");
  console.error(err);
  process.exit(1);
});
```

**Execution Flow**:
1. Load `.env.local` for `POSTGRES_URL`
2. Create connection with max 1 pool (safe for migrations)
3. Use Drizzle migrator to apply migrations from folder
4. Log timing and exit

## 10. Error Handling Patterns

### Try-Catch with Console Logging
All queries follow this pattern:

```typescript
export async function exampleQuery() {
  try {
    return await db.select().from(table).where(eq(table.id, id));
  } catch (error) {
    console.error("Failed to query X from database");
    throw error;
  }
}
```

**Pattern Characteristics**:
- Generic console.error messages (don't expose internal details)
- Always re-throws error for caller handling
- No silent failures

## Key Architectural Decisions

1. **Composite Primary Keys**: Document and Suggestion use (id, createdAt) to enable versioning
2. **JSON for Flexibility**: Attachments, parts, annotations stored as JSON for extensibility
3. **Cascade Deletes**: Foreign keys use CASCADE to automatically clean related records
4. **Application-Level UPSERT**: Vote operations use check-then-insert pattern
5. **External Cleanup**: Attachment URLs handled separately via Vercel Blob API
6. **Type Generation**: Automatic types from schema via InferSelectModel
7. **Server-Only Marking**: Query layer marked "server-only" to prevent client usage
8. **Timestamp Management**: Some tables handle updatedAt via `$onUpdate()`, others manually
