## Tool Definition & Registration

### Core Tool Structure

In AI SDK v5, tools are defined using the `tool()` helper function from the `ai` package. Each tool has three key elements:

- **`description`**: Influences when the model picks the tool
- **`inputSchema`**: Zod schema defining input parameters (replaces `parameters` from v4)
- **`execute`**: Optional async function that performs the tool action

**Source**: [AI SDK Tool Calling Documentation](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling)

### Basic Tool Definition

```typescript
import { z } from 'zod';
import { generateText, tool } from 'ai';
import { openai } from '@ai-sdk/openai';

const weatherTool = tool({
  description: 'Get the weather in a location',
  inputSchema: z.object({
    location: z.string().describe('The location to get the weather for'),
  }),
  execute: async ({ location }) => ({
    location,
    temperature: 72 + Math.floor(Math.random() * 21) - 10,
  }),
});

const result = await generateText({
  model: openai('gpt-4o'),
  tools: {
    weather: weatherTool,
  },
  prompt: 'What is the weather in San Francisco?',
});
```

### Tool Registration with OpenAI

Tools are passed as an object to `streamText` or `generateText`, with tool names as keys:

```typescript
const result = streamText({
  model: openai('gpt-4o'),
  tools: {
    semanticSearch: semanticSearchTool,
    fileRetrieve: fileRetrieveTool,
    // ... additional tools
  },
  messages: convertToModelMessages(messages),
});
```

### Input Schema Best Practices

- Use descriptive schema descriptions to guide the model
- Each parameter should have `.describe()` for clarity
- Use specific types (not generic `string` where more specific types apply)

```typescript
const semanticSearchTool = tool({
  description: 'Search vector store using semantic similarity',
  inputSchema: z.object({
    query: z.string().describe('The search query to find relevant documents'),
    limit: z.number().optional().describe('Maximum number of results (default: 5)'),
    threshold: z.number().optional().describe('Similarity score threshold (0-1)'),
  }),
  execute: async ({ query, limit = 5, threshold = 0.5 }) => {
    // Implementation
  },
});
```

## Streaming Tool Invocations

### Tool Call Streaming (Enabled by Default)

In AI SDK 5, tool call input streaming is **enabled by default**. This means tool inputs stream as they're generated by the model, providing partial updates to the UI.

**Source**: [AI SDK v5 Blog - Tool Improvements](https://vercel.com/blog/ai-sdk-5#tool-improvements)

### How Streaming Works

When using `streamText`, the response includes streaming tool call data:

```typescript
export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = streamText({
    model: openai('gpt-4o'),
    messages: convertToModelMessages(messages),
    tools: {
      semanticSearch: {
        description: 'Search the vector store',
        inputSchema: z.object({
          query: z.string(),
        }),
        execute: async ({ query }) => {
          // Perform search
          return { results: [...] };
        },
      },
    },
  });

  return result.toUIMessageStreamResponse();
}
```

### Accessing Tool Call IDs

The `execute` function receives tool metadata including the tool call ID:

```typescript
semanticSearch: tool({
  description: '...',
  inputSchema: z.object({ query: z.string() }),
  execute: async (args, { toolCallId }) => {
    // toolCallId identifies this specific tool invocation
    console.log(`Executing tool call: ${toolCallId}`);

    // Can use this to send status updates:
    // writer.write({
    //   type: 'data-tool-status',
    //   id: toolCallId,
    //   data: { status: 'in-progress' }
    // });

    return { /* results */ };
  },
})
```

**Source**: [AI SDK Tool Execution Options](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling#tool-execution-options)

## Tool Execution & Results

### Server-Side Tool Execution

For tools that execute on the server (automatic execution), include the `execute` function:

```typescript
const fileRetrieveTool = tool({
  description: 'Load a complete document from storage',
  inputSchema: z.object({
    documentId: z.string().describe('The ID of the document to retrieve'),
  }),
  execute: async ({ documentId }) => {
    // This runs server-side automatically
    const document = await loadDocument(documentId);
    return {
      id: documentId,
      content: document.content,
      metadata: document.metadata,
    };
  },
});
```

### Client-Side Tool Execution

For tools that need to run on the client (e.g., location access, user confirmation), omit the `execute` function and handle with `onToolCall`:

```typescript
// Server: Define tool without execute
const askForConfirmationTool = {
  description: 'Ask the user for confirmation',
  inputSchema: z.object({
    message: z.string(),
  }),
  // No execute function - client handles it
};

// Client: Handle with onToolCall callback
const { messages, addToolResult } = useChat({
  onToolCall: ({ toolCall }) => {
    if (toolCall.dynamic) return;

    if (toolCall.toolName === 'askForConfirmation') {
      // Show UI and collect user response
      addToolResult({
        tool: 'askForConfirmation',
        toolCallId: toolCall.toolCallId,
        output: userConfirmed ? 'Yes, confirmed.' : 'No, denied',
      });
    }
  },
});
```

### Multi-Step Tool Calls

Use `stopWhen` to enable agents to call multiple tools before responding:

```typescript
import { stepCountIs } from 'ai';

const result = await generateText({
  model: openai('gpt-4o'),
  tools: {
    semanticSearch: searchTool,
    fileRetrieve: fileTool,
  },
  stopWhen: stepCountIs(5), // Allow up to 5 steps
  prompt: 'Find relevant papers and summarize their content',
});

// Access all steps including tool calls and results
const allToolCalls = result.steps.flatMap(step => step.toolCalls);
```

**Source**: [AI SDK Multi-Step Calls](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling#multi-step-calls-using-stopwhen)

### Preliminary Tool Results (Streaming Tool Output)

Support streaming status updates during tool execution:

```typescript
const fileRetrieveTool = tool({
  description: 'Load a complete document from storage',
  inputSchema: z.object({ documentId: z.string() }),
  async *execute({ documentId }) {
    // First yield: loading state
    yield {
      status: 'loading' as const,
      message: `Loading document ${documentId}...`,
      content: undefined,
    };

    // Actual work
    const document = await loadDocument(documentId);

    // Final yield: success state
    yield {
      status: 'success' as const,
      message: 'Document loaded successfully',
      content: document.content,
    };
  },
});
```

The last value from the generator is the final tool result sent to the model.

## UI Integration & Display

### Tool Part Types (Type-Safe Rendering)

In AI SDK v5, each tool creates a typed part like `tool-TOOLNAME` instead of generic `tool-invocation`:

```typescript
// Each tool gets its own part type:
case 'tool-semanticSearch':
  return <SemanticSearchDisplay part={part} />;

case 'tool-fileRetrieve':
  return <FileRetrieveDisplay part={part} />;

case 'dynamic-tool':
  // For dynamic tools (MCP, runtime-defined)
  return <DynamicToolDisplay part={part} />;
```

### Tool Part States

Tool parts have a `state` property indicating their lifecycle:

- **`'input-streaming'`**: Tool input is being generated by the model
- **`'input-available'`**: Full input is available
- **`'output-available'`**: Tool has executed and result is ready
- **`'output-error'`**: Tool execution failed

**Source**: [AI SDK v5 Blog - Type-Safe Tool Invocations](https://vercel.com/blog/ai-sdk-5#type-safe-tool-invocations)

### Complete Chat UI Example

```typescript
'use client';

import { useChat } from '@ai-sdk/react';
import { lastAssistantMessageIsCompleteWithToolCalls } from 'ai';

export default function Chat() {
  const { messages, sendMessage, addToolResult } = useChat({
    api: '/api/chat',
    sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls,

    onToolCall: ({ toolCall }) => {
      if (toolCall.dynamic) return;

      // Handle client-side tools
      if (toolCall.toolName === 'askForConfirmation') {
        // Show confirmation dialog...
        addToolResult({
          tool: 'askForConfirmation',
          toolCallId: toolCall.toolCallId,
          output: userResponse,
        });
      }
    },
  });

  return (
    <>
      {messages?.map(message => (
        <div key={message.id}>
          <strong>{message.role}: </strong>

          {/* Render all message parts */}
          {message.parts.map((part, idx) => {
            switch (part.type) {
              case 'text':
                return part.text;

              case 'tool-semanticSearch': {
                const { state, input, output, toolCallId } = part;

                switch (state) {
                  case 'input-streaming':
                    return (
                      <div key={toolCallId} className="searching">
                        Searching: {JSON.stringify(input)}
                      </div>
                    );

                  case 'input-available':
                    return (
                      <div key={toolCallId} className="searching">
                        Searching for: {input.query}
                      </div>
                    );

                  case 'output-available':
                    return (
                      <div key={toolCallId} className="results">
                        Found {output.results.length} results
                      </div>
                    );

                  case 'output-error':
                    return (
                      <div key={toolCallId} className="error">
                        Search failed: {part.errorText}
                      </div>
                    );
                }
              }

              case 'tool-fileRetrieve': {
                const { state, input, output, toolCallId } = part;

                switch (state) {
                  case 'input-streaming':
                    return <div key={toolCallId}>Loading document...</div>;

                  case 'output-available':
                    return (
                      <div key={toolCallId} className="document">
                        <pre>{output.content.substring(0, 200)}...</pre>
                      </div>
                    );

                  case 'output-error':
                    return (
                      <div key={toolCallId} className="error">
                        Failed to load: {part.errorText}
                      </div>
                    );
                }
              }

              case 'dynamic-tool':
                return (
                  <div key={part.toolCallId}>
                    <h4>{part.toolName}</h4>
                    <pre>{JSON.stringify(part.input, null, 2)}</pre>
                  </div>
                );
            }
          })}
        </div>
      ))}

      {/* Input form */}
      <input
        value={input}
        onChange={e => setInput(e.target.value)}
        onKeyDown={e => {
          if (e.key === 'Enter') {
            sendMessage({ text: input });
            setInput('');
          }
        }}
      />
    </>
  );
}
```

**Source**: [AI SDK Chatbot Tool Usage](https://ai-sdk.dev/docs/ai-sdk-ui/chatbot-tool-usage)

## Error Handling

### Tool Execution Errors (Server-Side)

When tools fail on the server, errors are captured as `tool-error` content parts:

```typescript
const { steps } = await generateText({
  model: openai('gpt-4o'),
  tools: { /* ... */ },
  // ...
});

// Check for errors in steps
const toolErrors = steps.flatMap(step =>
  step.content.filter(part => part.type === 'tool-error'),
);

toolErrors.forEach(error => {
  console.log('Tool error:', error.error);
  console.log('Tool name:', error.toolName);
  console.log('Tool input:', error.input);
});
```

### Client-Side Tool Errors

Report errors from client-side tool execution:

```typescript
const { addToolResult } = useChat({
  onToolCall: async ({ toolCall }) => {
    if (toolCall.toolName === 'getLocation') {
      try {
        const location = await getUserLocation();
        addToolResult({
          tool: 'getLocation',
          toolCallId: toolCall.toolCallId,
          output: location,
        });
      } catch (err) {
        // Report error instead of output
        addToolResult({
          tool: 'getLocation',
          toolCallId: toolCall.toolCallId,
          state: 'output-error',
          errorText: 'Unable to access location: ' + (err as Error).message,
        });
      }
    }
  },
});
```

### Invalid Tool Input Errors

AI SDK provides structured error classes:

```typescript
import { NoSuchToolError, InvalidToolInputError } from 'ai';

try {
  const result = await generateText({
    model: openai('gpt-4o'),
    tools: { /* ... */ },
    // ...
  });
} catch (error) {
  if (NoSuchToolError.isInstance(error)) {
    // Model called non-existent tool
  } else if (InvalidToolInputError.isInstance(error)) {
    // Model provided invalid inputs
  }
}
```

### Error Handling in Streaming Responses

```typescript
const result = streamText({
  model: openai('gpt-4o'),
  tools: { /* ... */ },
  // ...
});

return result.toUIMessageStreamResponse({
  onError: (error) => {
    if (NoSuchToolError.isInstance(error)) {
      return 'The model tried to call an unknown tool.';
    } else if (InvalidToolInputError.isInstance(error)) {
      return 'The model called a tool with invalid inputs.';
    }
    return 'An unknown error occurred.';
  },
});
```

**Source**: [AI SDK Tool Calling - Error Handling](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling#handling-errors)

## Agent Decision-Making

### How Models Decide When to Use Tools

The AI SDK's `toolChoice` parameter controls tool selection behavior:

- **`'auto'` (default)**: Model can choose whether to call tools
- **`'required'`**: Model must call a tool
- **`'none'`**: Model cannot call tools
- **`{ type: 'tool', toolName: string }`**: Force specific tool

```typescript
const result = await generateText({
  model: openai('gpt-4o'),
  tools: {
    semanticSearch: searchTool,
    fileRetrieve: fileTool,
  },
  toolChoice: 'required', // Force the model to use a tool
  prompt: 'Find relevant information about RAG systems',
});
```

### Tool Selection Strategy

Models decide which tool to use based on:

1. **Tool description** - Most important factor
2. **Input schema** - Guides what parameters are available
3. **System prompt/context** - Task context influences choices
4. **Message history** - Previous interactions

**Good tool descriptions are crucial**:

```typescript
// Bad: Too vague
const tool1 = tool({
  description: 'Search',
  // ...
});

// Good: Clear purpose and use case
const semanticSearchTool = tool({
  description: 'Search the vector store using semantic similarity to find documents related to the user query. Use this when you need to find relevant information from the knowledge base.',
  inputSchema: z.object({
    query: z.string().describe('Natural language search query'),
  }),
  // ...
});

const fileRetrieveTool = tool({
  description: 'Load and retrieve the complete content of a specific document by ID. Use this when you need the full text of a document after finding it with semantic search.',
  inputSchema: z.object({
    documentId: z.string().describe('The exact ID of the document to retrieve'),
  }),
  // ...
});
```

### Multi-Step Agent Loops

Control agent behavior with `stopWhen` and `prepareStep`:

```typescript
import { stepCountIs, hasToolCall } from 'ai';

const result = await generateText({
  model: openai('gpt-4o'),
  tools: {
    search: searchTool,
    retrieve: fileTool,
    finalAnswer: finalAnswerTool,
  },
  stopWhen: hasToolCall('finalAnswer'), // Stop when this tool is called

  prepareStep: async ({ stepNumber, steps, messages }) => {
    // Customize behavior per step
    if (stepNumber === 0) {
      return {
        // Only allow search on first step
        activeTools: ['search'],
      };
    }

    if (stepNumber >= 3) {
      return {
        // Force final answer on step 3+
        toolChoice: { type: 'tool', toolName: 'finalAnswer' },
      };
    }

    return {}; // Use defaults for other steps
  },

  prompt: 'Answer the user question comprehensively',
});
```

**Source**: [AI SDK Agentic Loop Control](https://vercel.com/blog/ai-sdk-5#agentic-loop-control)

### Active Tools (Limiting Available Tools)

Reduce tool set dynamically to improve model performance:

```typescript
const result = await generateText({
```

## Best Practices

### 1. Tool Descriptions

- Be **specific** about what the tool does
- Explain **when** to use it (not when to use other tools)
- Include **input guidance** in the description
- Keep descriptions concise (1-2 sentences)

```typescript
// Good
const semanticSearchTool = tool({
  description: 'Search the knowledge base for documents related to a query using semantic similarity. Returns document summaries and IDs. Use this to find relevant information from existing documents.',
  inputSchema: z.object({ query: z.string() }),
  // ...
});

// Avoid
const semanticSearchTool = tool({
  description: 'Search', // Too vague
  // ...
});
```

### 2. Input Schema Design

- Use **Zod descriptions** to guide input
- Make **optional parameters truly optional**
- Provide **reasonable defaults**
- Use **specific types** (not generic strings)

```typescript
const searchTool = tool({
  description: '...',
  inputSchema: z.object({
    query: z.string()
      .describe('The search query - be specific and use keywords'),
    limit: z.number()
      .int()
      .min(1)
      .max(20)
      .optional()
      .describe('Max results to return (default: 5)'),
    filters: z.object({
      dateFrom: z.string().optional(),
      dateUntil: z.string().optional(),
    }).optional(),
  }),
  // ...
});
```

### 3. Tool Ordering

Register tools in your `tools` object with more specific tools first:

```typescript
const result = streamText({
  model: openai('gpt-4o'),
  tools: {
    // Most specific/commonly used first
    semanticSearch: searchTool,
    fileRetrieve: fileTool,

    // Less frequently used
    askConfirmation: confirmationTool,
  },
});
```

### 4. Handle Tool Failures Gracefully

Always implement error handling:

```typescript
const searchTool = tool({
  description: '...',
  inputSchema: z.object({ query: z.string() }),
  execute: async ({ query }) => {
    try {
      const results = await vectorStore.search(query, { limit: 5 });
      return { success: true, results };
    } catch (err) {
      // Return error information instead of throwing
      return {
        success: false,
        error: `Search failed: ${(err as Error).message}`,
        results: [],
      };
    }
  },
});
```

### 5. Type Safety with Custom Message Types

Define custom types for your specific tools:

```typescript
import { TypedToolCall, TypedToolResult } from 'ai';

const myTools = {
  semanticSearch: searchTool,
  fileRetrieve: fileTool,
};

type MyToolCall = TypedToolCall<typeof myTools>;
type MyToolResult = TypedToolResult<typeof myTools>;

// Now use these types for full type safety
const handleToolCall = (toolCall: MyToolCall) => {
  // TypeScript knows exactly which tools are available
};
```

### 6. Tool Execution Context

Use the execution options to access context:

```typescript
const searchTool = tool({
  description: '...',
  inputSchema: z.object({ query: z.string() }),
  execute: async (
    { query },
    {
      toolCallId,      // ID of this specific invocation
      messages,        // Message history
      abortSignal,     // For cancellation
    }
  ) => {
    // Use these to customize behavior
    console.log(`Executing tool call: ${toolCallId}`);

    // Forward abort signal to fetch/async operations
    const results = await vectorStore.search(query, {
      signal: abortSignal,
    });

    return results;
  },
});
```

## Complete Example

### Server API Route (Next.js)

```typescript
// app/api/chat/route.ts
import { openai } from '@ai-sdk/openai';
import { convertToModelMessages, streamText, tool } from 'ai';
import { z } from 'zod';

export const maxDuration = 30;

// Tool implementations
const semanticSearchTool = tool({
  description: 'Search the vector store using semantic similarity to find documents related to the query. Returns relevant document IDs and summaries.',
  inputSchema: z.object({
    query: z.string().describe('The search query'),
    limit: z.number().optional().default(5),
  }),
  execute: async ({ query, limit }) => {
    // Your vector store implementation
    const results = await searchVectorStore(query, { limit });
    return {
      success: true,
      results: results.map(r => ({
        id: r.id,
        score: r.similarity,
        summary: r.content.substring(0, 200),
      })),
    };
  },
});

const fileRetrieveTool = tool({
  description: 'Load and return the complete content of a specific document. Use after finding the document ID with semantic search.',
  inputSchema: z.object({
    documentId: z.string().describe('The document ID to retrieve'),
  }),
  execute: async ({ documentId }) => {
    const doc = await loadDocument(documentId);
    if (!doc) {
      throw new Error(`Document not found: ${documentId}`);
    }
    return {
      id: documentId,
      title: doc.title,
      content: doc.content,
      metadata: doc.metadata,
    };
  },
});

export async function POST(req: Request) {
  const { messages } = await req.json();

  const result = streamText({
    model: openai('gpt-4o'),
    messages: convertToModelMessages(messages),
    tools: {
      semanticSearch: semanticSearchTool,
      fileRetrieve: fileRetrieveTool,
    },
    system: 'You are a helpful assistant that helps users find and understand documents. Use the semantic search tool to find relevant documents, then use file retrieve to get their full content when needed.',
    prompt: messages[messages.length - 1]?.content,
  });

  return result.toUIMessageStreamResponse();
}
```

```typescript
                      )}
                      {state === 'output-error' && (
                        <div className="text-sm text-red-600">
                          Failed to load: {part.errorText}
                        </div>
                      )}
                    </div>
                  );
                }

                case 'dynamic-tool':
                  return (
                    <div
                      key={part.toolCallId}
                      className="bg-gray-50 p-3 rounded mb-2"
                    >
                      <div className="font-semibold">{part.toolName}</div>
                      <pre className="text-xs mt-2 overflow-auto">
                        {JSON.stringify(part.input, null, 2)}
                      </pre>
                    </div>
                  );

                default:
                  return null;
              }
            })}
          </div>
        ))}
      </div>

      {/* Input */}
      <div className="border-t p-4">
        <div className="flex gap-2">
          <input
            value={input}
            onChange={(e) => setInput(e.target.value)}
            onKeyDown={(e) => {
              if (e.key === 'Enter' && input.trim()) {
                sendMessage({ text: input });
                setInput('');
              }
            }}
            placeholder="Ask a question..."
            className="flex-1 px-4 py-2 border rounded"
          />
          <button
            onClick={() => {
              if (input.trim()) {
                sendMessage({ text: input });
                setInput('');
              }
            }}
            className="px-4 py-2 bg-blue-600 text-white rounded"
          >
            Send
          </button>
        </div>
      </div>
    </div>
  );
}
```

## Key Takeaways

1. **Tool Definitions**: Use `tool()` helper with `description`, `inputSchema`, and `execute`
2. **Streaming**: Tool inputs stream by default; handle with `state` property in UI
3. **Type Safety**: Each tool gets typed part (`tool-TOOLNAME`) in messages
4. **Multi-Step**: Use `stopWhen` and `prepareStep` for agentic loops
5. **UI Display**: Render different content based on `state` (streaming, available, error)
6. **Error Handling**: Catch errors server-side and report to client
7. **Decision Making**: Models choose tools based on descriptions and context
8. **Client vs Server**: Some tools execute server-side (with `execute`), others need client interaction
