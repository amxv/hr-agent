## Issues Found

### Medium Priority Issues

#### 1. Incomplete Seed Data for Non-Primary Employees

**Location:** `lib/db/seeds/hr-data.ts:167-218`
**Severity:** Medium
**Issue:** Only John Doe (EMP001) has leave balances seeded. The other 4 initial employees (Noor, Maria, Ahmed, Jennifer) do not have leave balance records created.

**Impact:** Incomplete demo data; if admin tries to view leave balances for other employees, they will find empty records.

**Recommendation:** Extend `seedLeaveBalances()` to create leave balances for all 5 initial employees, not just John Doe.

```typescript
// Suggested fix: Create leave balances for all employees
for (const emp of employees) {
  await db.insert(leaveBalance).values([
    { employeeId: emp.id, leaveType: "vacation", currentBalance: "15", ... },
    { employeeId: emp.id, leaveType: "sick", currentBalance: "10", ... },
    { employeeId: emp.id, leaveType: "personal", currentBalance: "3", ... },
  ]);
}
```

#### 2. Incomplete Benefits Enrollment Seed Data

**Location:** `lib/db/seeds/hr-data.ts:497-557`
**Severity:** Medium
**Issue:** Only John Doe has benefits enrollment seeded. Other employees have no enrollment records.

**Impact:** Incomplete demo data for benefits management demonstrations.

**Recommendation:** Create enrollment records for at least 2-3 employees to demonstrate variety in plan selections.

#### 3. Missing Coverage Percent Calculation in createLeaveRequest

**Location:** `lib/db/queries.ts:2214-2267`
**Severity:** Medium
**Issue:** The phase plan specifies "Calculate coverage impact" but `createLeaveRequest()` does not calculate `coveragePercent`. The seed data hardcodes this value.

**Impact:** Coverage percent will be null or incorrect for leave requests created via admin panel.

**Recommendation:** Add coverage calculation logic:
```typescript
// After conflict detection, add:
const { calculateCoveragePercent } = await import("@/lib/hr/helpers");
const teamMembers = await db
  .select()
  .from(employee)
  .where(eq(employee.department, employeeDepartment));
const coveragePercent = calculateCoveragePercent(
  teamMembers.length,
  existingAbsences,
  new Date(data.requestedStartDate)
);
```

#### 4. Employee Creation Schema Mismatch

**Location:** `trpc/routers/admin.router.ts:304-345`
**Severity:** Medium
**Issue:** The `createEmployee` procedure requires input fields (`city`, `country`, `timezone`, `hireDate`) that do not exist in the employee schema from Phase 1.

**Impact:** This will cause runtime errors when trying to create employees through the admin UI.

**Recommendation:** Review the employee schema from Phase 1 and update the input validation to match the actual schema fields. Remove non-existent fields from the input schema.

#### 5. Self-Approval Bug in approveLeaveRequest

**Location:** `lib/db/queries.ts:2305`
**Severity:** Medium
**Issue:** When creating an absence from an approved leave request, the `approvedBy` field is set to `request.employeeId` (self-approval) instead of using the `reviewedBy` parameter.

**Code:**
```typescript
approvedBy: request.employeeId, // Self-reference for now
```

**Impact:** Absence records will incorrectly show employees approving their own time off instead of showing who actually approved it.

**Recommendation:**
```typescript
approvedBy: reviewedBy, // Use the actual reviewer
```

#### 6. Missing Validation for Manager Relationships

**Location:** `trpc/routers/admin.router.ts:304-345, 347-375`
**Severity:** Medium
**Issue:** Neither `createEmployee` nor `updateEmployee` procedures validate that `managerId` refers to an existing employee. This can lead to broken foreign key relationships.

**Impact:** Could create data integrity issues with orphaned manager references.

**Recommendation:** Add validation to check that managerId exists:
```typescript
if (input.managerId) {
  const manager = await db.select().from(employee).where(eq(employee.id, input.managerId)).limit(1);
  if (manager.length === 0) {
    throw new TRPCError({
      code: "BAD_REQUEST",
      message: "Manager not found"
    });
  }
}
```

#### 7. Leave Balance Update Missing Validation

**Location:** `trpc/routers/admin.router.ts:403-423`
**Severity:** Medium
**Issue:** The phase plan specifies validation that `currentBalance >= 0` but this is not implemented in the `updateLeaveBalance` procedure.

**Impact:** Admins could set negative leave balances, which violates business logic.

**Recommendation:** Add validation before the update:
```typescript
if (input.data.currentBalance !== undefined) {
  const balance = parseFloat(input.data.currentBalance);
  if (balance < 0) {
    throw new TRPCError({
      code: "BAD_REQUEST",
      message: "Leave balance cannot be negative"
    });
  }
}
```
