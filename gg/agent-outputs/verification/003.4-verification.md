#### 4. "none" Sentinel Value Not Filtered ⚠️
**Impact**: MEDIUM - Could cause backend validation errors

**File**: `components/admin/edit-enrollment-dialog.tsx` (lines 205, 272, 338)

**Issue**: Uses string "none" as sentinel value for no plan selected, but doesn't filter it out before submitting:
```typescript
<Select onValueChange={field.onChange} value={field.value || "none"}>
  <SelectItem value="none">No Plan</SelectItem>
  {medicalPlans?.plans.map((plan) => (
    <SelectItem key={plan.id} value={plan.id}>...</SelectItem>
  ))}
</Select>
```

**Consequences**: If user selects "No Plan", the string "none" is sent to backend which likely expects `undefined`, `null`, or an actual UUID.

**Required Fix**: Convert "none" to undefined in onSubmit:
```typescript
const onSubmit = async (values: EditEnrollmentFormValues) => {
  await trpcClient.admin.hr.enrollments.upsert.mutate({
    employeeId: enrollment.enrollment.employeeId,
    medicalPlanId: values.medicalPlanId === "none" ? undefined : values.medicalPlanId,
    // ... same for dental and vision
  });
};
```

**Plan Reference**: Section 8 (lines 181-200) - Edit Enrollment Dialog
